# 手順 3: 画面を S3 でホスティングする

## ゴール

- 画面のファイル（HTML/JS/CSS）を S3 バケットに置き、静的ウェブサイトとして公開する
- S3 の画面から EC2 上の API を呼び出し、同じようにメッセージが表示・追加できる

## 3-0. 考え方

手順 2 では、画面と API が同じ EC2 の同じ 80 番ポートにいました。
Nginx が `/api/*` だけを FastAPI に中継していたので、ブラウザから見れば「全部同じサーバー」でした。

```
手順 2:  ブラウザ ──> EC2:80 (Nginx) ──┬─ 画面 (HTML/JS)
                                        └─ /api → FastAPI
```

S3 に画面を移すと、画面の配信元と API の場所が別になります。

```
手順 3:  ブラウザ ──> S3 (画面)
            └──────> EC2:8000 (FastAPI)   ← 別のサーバーへ直接
```

このとき 2 つのことが必要です。

1. **画面側**: API の接続先を「同じ場所の `/api`」から「`http://<EC2 の IP>:8000`」に変える
2. **API 側**: 別のオリジン（S3）からの呼び出しを許可する **CORS** 設定を入れる

この教材では、1 は `config.js` という 1 ファイルを差し替えるだけで済むようにしてあります（再ビルド不要）。
2 の CORS（Cross-Origin Resource Sharing）は「別のサイトからの JavaScript 呼び出しを許可するか」をサーバーが宣言する仕組みで、API は既に `CORS_ORIGINS=*`（すべて許可）で起動しているので済んでいます。

## 3-1. S3 用のファイルを出力する

### 方法 A: 画面のボタンから（おすすめ）

1. ブラウザで `http://<EC2 の IP>/` を開く
2. 左下のダウンロードのアイコン（S3 用ファイルの書き出し）を押す
3. 「API の接続先」が `http://<EC2 の IP>:8000` になっていることを確認する（自動で入ります）
4. 「zip をダウンロード」を押す → `s3-static-site.zip` が自分の PC に落ちる
5. 解凍する。中身は次のとおり

```
index.html
config.js          ← API 接続先が書かれている
assets/index-xxxx.js
assets/index-xxxx.css
README_S3.txt      ← 手順メモ
```

### 方法 B: EC2 のターミナルから

```bash
cd ~/HandsOn-3ogyqbi3tg2
bash scripts/build_for_s3.sh http://<EC2 のパブリック IP>:8000
```

`web/dist/` に同じ内容が出力されます。

> どちらの方法でも、IP を間違えると S3 の画面は表示されるのに「API: NG」になります。
> その場合は `config.js` の中身を直して再アップロードするだけで直ります。

## 3-2. S3 にアップロードして公開する

### 方法 A: コンソールから（PC に zip を落とした人）

1. S3 → **バケットを作成**。名前は世界で一意なので `training-<自分の名前>-20261031` のように
2. 「このバケットのブロックパブリックアクセス設定」を **すべてオフ**にして作成
3. バケット → **アクセス許可** → **バケットポリシー** → 編集。`<バケット名>` を置き換えて貼り付け

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [{
       "Sid": "PublicReadGetObject",
       "Effect": "Allow",
       "Principal": "*",
       "Action": "s3:GetObject",
       "Resource": "arn:aws:s3:::<バケット名>/*"
     }]
   }
   ```

4. バケット → **プロパティ** → 一番下の **静的ウェブサイトホスティング** → 編集 → 有効化。
   インデックスドキュメント `index.html`、エラードキュメント `index.html`
5. バケット → **オブジェクト** → **アップロード**。解凍したフォルダの**中身**（`index.html` と `assets` フォルダなど）をドラッグ
   注意: フォルダごとではなく中身を入れる。`index.html` がバケットのルート直下に来ること
6. プロパティ → 静的ウェブサイトホスティングに表示される URL を開く

### 方法 B: EC2 のターミナルから（IAM ロールが付いている人）

```bash
bash scripts/deploy_to_s3.sh training-<自分の名前>-20261031
```

バケット作成、公開設定、ホスティング有効化、アップロードを一括で行い、最後に URL を表示します。
`AccessDenied` が出たら EC2 に S3 権限のある IAM ロールが付いていません（手順 1 参照）。

## 3-3. 動作を確認する

```
http://<バケット名>.s3-website-ap-northeast-1.amazonaws.com
```

> 注意: **`http://`** で開きます。S3 の静的ホスティングは https 非対応です（https にするには CloudFront が必要）。

次を確認します。

- アドレスバーが S3 の URL になっている
- 開発者ツールの「ネットワーク」タブで、`/api/...` の宛先が `<EC2 の IP>:8000` になっている
- 手順 2 と同じアカウントでログインでき、トークの内容もそのまま見える（同じ DB を見ているから）
- 左下が「● 接続中」になり、EC2 側の画面との間でメッセージがリアルタイムに届く
  （WebSocket も `ws://<EC2 の IP>:8000/api/ws` へ直接つながっています）

## 3-4. 試してみよう（任意）

- EC2 で `docker compose stop api` すると S3 の画面はどうなるか？（画面は出るがログインできず、左下が「○ 再接続中...」になる）
- セキュリティグループから 8000 番を外すとどうなるか？
- `config.js` の IP をわざと間違えて上書きアップロードし、画面の表示を見てから直す
- `.env` に `CORS_ORIGINS=http://<バケット名>.s3-website-ap-northeast-1.amazonaws.com` を書いて
  `docker compose up -d` し、許可するオリジンを絞ってみる

## 片付け

```bash
aws s3 rb s3://training-<自分の名前>-20261031 --force   # バケットごと削除 (コンソールからでも可)
docker compose down -v                                   # EC2 側のコンテナと DB を削除
```

最後に EC2 インスタンスを終了（削除）してください。

- [ ] API / DB ともに OK で、メッセージの追加もできる
